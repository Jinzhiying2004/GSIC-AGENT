# GSIC 横屏模式设计

> 实施状态（2026-11-02）：v1 已在 v3.95/207 实现，横屏 tab
> 右侧竖栏已在 v3.96/208 实现并推送到 GT 直接安装。
> 重要更正：20:09 的“底部 tab 不变位置”与 20:16 的“同样位置”
> 被我误读成“横屏 tab 仍在底部”，用户 20:20 亲定纠正：
> 横屏时 tab 应该在右侧。3.95 的“底部不动”已作废，
> 以 3.96 的右侧竖栏为准；下文凡写“底部不动”的地方，
> 均以本条更正覆盖。

## 现状（2026-11-02 实测代码）

- Manifest 里 MainActivity 没有 screenOrientation，也没有 configChanges，
  也就是说系统默认会跟随旋转，但 Activity 会在旋转时重建。
- UI 全是代码写的（无 XML layout）：根是 FrameLayout，里面是纵向
  LinearLayout content（5 个页面叠放，showPage 只显示一个），底部是
  悬浮胶囊 tabBar（主页 / 远控 / 智能体 / 终端 / 我的）。
- 各页全是纵向 LinearLayout + ScrollView，底部留 dp(100) 避让悬浮 tab。
- 旋转重建的后果：tab 靠 prefs 里的 "ui" tab 能恢复，但代码生成的
  EditText 没有 id，系统自动保存恢复不到，输入框草稿、滚动位置、
  终端输入等在旋转时容易丢；纵向单列在横屏下只是被拉宽，高度
  反而只剩约 360-400dp，悬浮 tab + 输入栏一占，内容所剩无几。
- windowSoftInputMode 已是 adjustResize，键盘弹出时内容会压缩，
  不会盖住输入栏，这是横屏已有的好底子。

## 目标

- 横屏不是“竖屏拉宽”，而是“宽屏换布局”：用宽度换信息密度，
  底部 tab 位置不动，旋转不丢东西。
- 底部 tab 不变位置（2026-11-02 20:09 用户亲定，20:16 进一步
  明确）：横屏下 tab 仍在底部，仍是现在的悬浮胶囊样式与位置，
  不改成左侧导航轨。竖屏时 tab 在什么位置，横屏就要在同样
  的位置：底部居中、左右边距 16dp、底部边距 16dp 不变，
  只是图标随屏幕旋转而转正（系统转屏时整个窗口转，tab 与
  图标自然跟着转，不需要单独处理图标方向）。竖屏体验一动
  不动，横屏只在宽度大于高度时切换，窄屏横屏（小窗、分屏）
  仍走竖屏布局。
- 不引入新依赖，不改三端协议（Telegram / App / 远控），只改
  MainActivity 的根布局与各页的排列方式。

## 原则

1. 跟随系统，不强制：默认跟随系统旋转，不锁竖屏也不锁横屏。
2. 旋转不丢东西：当前 tab、输入草稿、滚动位置、聊天消息、终端
   输出在旋转前后必须一致，宁可不重建 Activity，也不要重建后丢草稿。
3. 高度优先于宽度：横屏最缺的是高度，任何常驻元素（底部 tab、
   输入栏、顶栏）都要先算高度账，再算宽度账；底部 tab 不动，
   所以横屏的高度账比侧栏方案更紧，内容区要先把 tab 的位置
   让出来。
4. 一页一策，不搞一刀切：菜单+详情页用分栏，聊天/终端用满宽，
   我的页用居中限宽，文字行不拉到 800dp 以上。

## 总体布局

### 竖屏（现状，不变）

- FrameLayout 根，content 纵向，底部悬浮胶囊 tab（左右边距 16dp、
  底部边距 16dp，半透明毛玻璃），内容底部留 dp(100) 避让。
- 各页单列 ScrollView，卡片全宽。

### 横屏（新，tab 在右侧竖栏，v3.96，覆盖“底部不动”）

- 根布局仍是 FrameLayout + 纵向 content + 悬浮胶囊 tab，
  但 tab 在横竖屏下换位置：竖屏在底部横向（MATCH_PARENT 宽、
  BOTTOM|CENTER_HORIZONTAL、边距 16/0/16/16），横屏在右侧
  竖栏（WRAP_CONTENT 宽高、RIGHT|CENTER_VERTICAL、边距
  0/16/16/16，栏宽约 68dp，每图标 56x46dp、纵向排列）。
- 图标在右侧栏内方向正对横屏（不是横着的）：TabIconView
  本身不旋转，只是从横向排列改成纵向排列，图标绘制仍按
  视图宽高居中，选中胶囊底仍由图标视图自绘。
- 内容区在横屏下右留 84dp（栏宽 68dp + 右边距 16dp）避让
  右侧 tab，tab 隐藏时（输入中）不留白；各页原有的 dp(100)
  底部避让保留。
- 输入时隐藏 tab 的逻辑保留，方向改过来：横屏向右滑出隐藏、
  竖屏向下滑出隐藏，恢复时两个方向的位移都清零。
- 判定条件：只在 orientation == LANDSCAPE 且宽度 >= 600dp 时
  走横屏内容布局；宽度 < 600dp 的横屏（小窗、分屏、折叠半屏）
  仍走竖屏单列布局。
- 彩条：内嵌流光条仍挂在根布局最上层，不消费触摸，横屏时
  沿顶部全宽显示，与竖屏一致。

## 各页横屏

### 主页 / 远控：菜单 + 详情分栏

- 现在是“菜单页 → 点一行 → 全屏详情页 → 返回菜单”的两级结构，
  横屏改成左右分栏同时显示：
  - 左栏：菜单列表，宽 320dp（或内容宽的 38%，取较小者），
    全高可滚动，与竖屏菜单同一批行。
  - 右栏：详情 ScrollView，占剩余宽度，全高可滚动。
  - 点菜单行只换右栏内容，不隐藏左栏；右栏顶部的“返回”按钮
    在横屏下隐藏（因为菜单一直在），竖屏下保留。
  - 左右两栏高度都受底部 tab 限制：两栏底部都留 dp(100)
    避让，滚动到底时最后一行不被 tab 盖住。
- 远控页的卡片（服务 / CF / tsnet / 中继 / Muse / TG / API /
  任务 / 设置）在右栏里单列显示，卡片限宽 720dp 居中，避免
  tsnet 登录链接、auth key 输入框被拉到超宽。
- 主页同理：左栏是主页菜单，右栏是详情。

### 智能体（聊天）：满宽消息 + 底部输入

- 消息列表仍满宽，气泡最大宽度从现在的全宽收为内容宽的 75%，
  避免横屏下一行字过长难读；时间、头像等不变。
- 输入栏在内容底部，高度紧凑：单行起，自动增高到最多 4 行，
  再多则输入框内滚动，不把消息区压没。
- 技能卡、风险提示、模型选择这些原来在消息区上方的附属区，
  横屏下不常驻，点对应按钮时在消息区上方弹出，关掉即回消息区。
- 输入时 tab 仍自动隐藏：tab 在底部，与输入栏同处底部，
  竖屏那套“输入时隐藏悬浮 tab”的逻辑在横屏下保留不变，
  输入栏获得高度后 tab 再恢复。

### 终端：满宽最受益

- 终端输出满宽显示，长命令换行次数直接减少，这是横屏收益最大的一页。
- 输入栏在内容底部，与竖屏同一套（命令输入 + 发送），底部 tab
  仍在，输入时 tab 自动隐藏的逻辑不变。
- 输出区仍可滚动，键盘弹出时 adjustResize 压缩输出区，不盖输入栏。

### 我的：居中限宽

- 我的页卡片（自检、关于、日志、监管者、更多、用户资料等）
  不拉满宽：内容区限宽 720dp 居中，两侧留白，文字行保持可读。
- 卡片仍单列滚动，不做两列网格：我的页卡片高度不一、内容长，
  两列对齐反而难读，限宽单列是最稳的横屏形态。
- “我的页连点 GSIC 标题 5 次”彩蛋等交互不变，只在顶栏位置上。

## 旋转处理（关键，不丢东西）

- Manifest 给 MainActivity 加：
  configChanges="orientation|screenSize|screenLayout|keyboardHidden"
- MainActivity 实现 onConfigurationChanged()，只重排根布局，
  不重建 Activity：
  - 重排前先记下：当前 tab、每个输入框的文字（智能体输入、
    终端输入、tsnet key 输入等）、各 ScrollView 的 scrollY、
    当前打开的菜单/详情（主页、远控）。
  - 重排时：按新方向重排内容区内部（横屏分栏 / 限宽，或竖屏
    单列），根布局与底部 tab 不动，各页视图复用已建好的
    pageHome / pageRemote / pageAgent / pageTerm / pageMy，
    不重新 build（build 只在 onCreate 做一次）。
  - 重排后恢复：tab、输入文字、滚动位置、菜单/详情状态，
    再调一次 refreshTsnetCard / refreshAll 这类刷卡面的方法。
- 兜底：如果重排中抛异常，允许走一次 Activity 重建（删
  configChanges 的临时绕法不做），重建后 tab 仍靠 prefs 恢复，
  输入草稿在重建前已写进 prefs 备份（见下）。
- 输入草稿备份：各输入框在文字变化时（已有监听的地方顺带）
  把草稿写进 prefs "ui" 下的 draft 键，旋转、进程被杀后回来
  也能恢复；发送成功后清掉该键，不留旧草稿。

## 键盘与高度账（横屏约 360dp 高时）

- 顶栏约 48dp + 输入栏约 56dp + 状态栏约 24dp + 底部 tab
  约 80dp（含边距）= 约 208dp，留给消息/终端输出区约
  150dp 左右，输入时 tab 自动隐藏后可还回约 80dp，这是
  横屏高度紧张的根源，也是分栏与限宽必须先算高度账的原因。
- 键盘弹出时：adjustResize 已有，输出区再压缩，输入栏必须
  始终可见，不被键盘盖住；tab 在输入时已隐藏，不再额外占高。
- 底部 tab 不动，所以 dp(100) 底部留白在横屏下保留，不靠
  取消留白来凑高度；高度靠分栏（菜单与详情并排，各自滚动）
  与输入时隐藏 tab 来换。

## 设置

- 设置页（统一设置分组里）新增一项“屏幕方向”：
  跟随系统（默认）/ 仅竖屏 / 仅横屏。
  - 仅竖屏：Manifest 仍不锁，代码里在 onCreate 与
    onConfigurationChanged 里强制竖屏布局（即使系统横屏，
    也按竖屏布局画，内容居中限宽）。
  - 仅横屏：同理强制横屏布局（适合长期横屏支架、车载等场景）。
  - 该设置只影响 App 内布局，不改系统旋转锁，不申请新权限。
- 该设置变更立即生效，不用重启 App：改完调一次重排逻辑即可。

## 验收（装机必测）

1. 竖屏与之前一模一样：胶囊 tab、单列、底部留白、彩条、彩蛋。
2. 横屏切过去：底部 tab 位置、大小、样式与竖屏完全一致，
   内容区主页/远控分栏、智能体消息 75% 气泡、终端满宽、
   我的限宽 720dp 居中，底部留白不被 tab 盖住。
3. 旋转不丢：智能体输入框打一半字、终端输一半命令、远控停在
   tsnet 卡、主页停在某详情，旋转后 tab、草稿、滚动、详情全在。
4. 键盘：横屏下智能体、终端输入时键盘弹出，输入栏可见，
   消息/输出区可滚动，不被盖住。
5. 小窗/分屏：宽度 < 600dp 的横屏仍走竖屏布局，横屏分栏不出现。
6. 三端：Telegram / App / 远控功能不变，只改 App 内布局；
   远控 /task、/action、截图等不受横屏影响。

## 实施分步（建议，不一次全上）

- 第一步（v1，必做）：Manifest configChanges + onConfigurationChanged
  重排 + 横屏内容分栏（tab 不动）+ 我的限宽 + 方向设置项。
  这一步已覆盖 80% 的横屏收益，代码只动 MainActivity 与 Manifest。
- 第二步（v2，可选）：智能体气泡 75% 限宽、附属区弹出化、
  终端行号/换行优化、横屏下输入栏 4 行上限。
- 不做：平板专属布局、横屏专属主题色、强制横屏的游戏式全屏、
  旋转动画（系统默认即可，不自写动画防卡顿）。

## 与现有规矩的关系

- 发版策略不变：能热更新就热更新，但布局重排涉及 MainActivity
  根布局与 Manifest，热补丁装不下时走整包，整包必须包含
  全部热更新内容。
- 三端横扫：只改 App 内布局，Telegram 与远控通道不受影响，
  但发版前仍按铁律过三端检查表。
- 版本：按每次迭代 +0.01，横屏 v1 单次不超 5 个功能则 +0.01，
  若 v1+v2 合并一次超 5 个功能则 +0.1。
